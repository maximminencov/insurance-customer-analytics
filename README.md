# Insurance Customer Analytics

## О проекте

End-to-end аналитический проект по страховым данным: от интеграции нескольких источников и построения витрины данных до сегментации клиентов, A/B-тестирования новой схемы ценообразования и подготовки бизнес-рекомендации.

Проект показывает полный аналитический цикл:

**Data Integration → Data Quality → Anomaly Detection → Customer Segmentation → A/B Testing → Business Recommendation**

## Бизнес-задача

Страховая компания рассматривает новую схему ценообразования, основанную на клиентской сегментации.

Необходимо было:

- объединить данные из нескольких источников;
- подготовить единую страховую витрину;
- проверить и повысить качество данных;
- выявить аномальные наблюдения;
- определить основные клиентские сегменты;
- оценить различия в страховых рисках между сегментами;
- сравнить традиционную и новую схемы ценообразования с помощью A/B-теста;
- сформулировать рекомендацию для бизнеса.

## Этап 1. Интеграция данных

Исходные данные включали несколько Excel-источников:

- страховые договоры;
- данные клиентов;
- страховые убытки.

Дополнительно использовались данные о курсах валют из внешнего API.

На этом этапе:

- данные были объединены в единую аналитическую витрину;
- добавлены клиентские характеристики;
- информация о договорах сопоставлена со страховыми выплатами;
- денежные показатели были приведены к единой валюте;
- сформированы показатели стоимости полиса, страховой суммы и убытков в USD.

## Этап 2. Data Quality и поиск аномалий

После построения витрины был проведён анализ качества данных.

Итоговая очищенная витрина:

- **3 711 наблюдений**
- **17 признаков**
- **0 пропусков**
- **0 полных дубликатов**

Для выявления аномалий был пересмотрен первоначальный подход.

Редкие наблюдения не интерпретировались автоматически как ошибочные. Вместо глобального сравнения аномалии определялись внутри сопоставимых страховых продуктов.

Дополнительно был создан относительный показатель:

`premium_rate_per_day`

Итог:

- обычные наблюдения — **3 599**
- аномальные наблюдения — **112**
- доля аномалий — около **3,02%**

Ключевой вывод:

> Редкость наблюдения не означает ошибку. Для корректного anomaly detection необходимо сначала определить правильную группу сравнения.

## Этап 3. Сегментация клиентов

Для сегментации использовались **3 315 действующих страховых полисов**.

Основная модель строилась на признаках:

- `age`
- `duration`
- `price_usd`
- `insurance_amount_usd`

Перед кластеризацией числовые признаки были стандартизированы.

Были протестированы:

- Hierarchical Clustering
- K-Means
- кластеризация с использованием расширенного набора признаков после One-Hot Encoding

### Выбор числа кластеров

Иерархическая кластеризация:

- лучший `silhouette_score = 0.7742` при `k = 2`

K-Means:

- `silhouette_score = 0.7742` при `k = 2`
- `silhouette_score = 0.4640` при `k = 3`

Несмотря на более высокий silhouette score для `k = 2`, для бизнес-интерпретации была выбрана сегментация на **3 кластера**, поскольку она позволила выделить отдельную группу долгосрочных дорогих полисов.

### Профили сегментов

| Сегмент | Клиентов | Типичный профиль | Claim rate |
|---|---:|---|---:|
| Cluster 0 | 1 599 | короткие полисы, высокая страховая сумма | 1.88% |
| Cluster 1 | 111 | долгосрочные дорогие полисы | 3.60% |
| Cluster 2 | 1 605 | массовый бюджетный сегмент | 0.69% |

Наиболее рискованным оказался небольшой сегмент долгосрочных дорогих полисов с максимальной частотой страховых выплат.

## Этап 4. A/B-тест новой схемы ценообразования

После сегментации была протестирована альтернативная pricing-модель.

В эксперимент вошли **12 349 уникальных участников**:

- Control — **6 043**
- Test — **6 306**

### Конверсия

| Группа | Участники | Оформили полис | Conversion |
|---|---:|---:|---:|
| Control | 6 043 | 1 949 | 32.25% |
| Test | 6 306 | 1 667 | 26.44% |

Абсолютное снижение конверсии:

**-5.82 п.п.**

Относительное снижение:

**-18.04%**

Welch t-test:

- `t = 7.1063`
- `p-value < 0.001`

Снижение конверсии статистически значимо.

### Цена полиса

Средняя стоимость оформленного полиса:

- Control — **47.70 USD**
- Test — **59.93 USD**

Рост:

**+25.64%**

### Выручка на участника

- Control — **15.38 USD**
- Test — **15.84 USD**

Рост:

**+2.98%**

Существенный рост цены почти полностью компенсируется падением конверсии.

## Убыточность и финансовый результат

Наблюдаемая убыточность:

- Control — **77.75%**
- Test — **88.49%**

Изменение:

**+10.74 п.п.**

Средний финансовый результат на участника:

- Control — **3.42 USD**
- Test — **1.82 USD**

Наблюдаемое изменение:

**-46.72%**

Welch t-test для финансового результата:

- `t = 0.2056`
- `p-value = 0.8371`

Статистически значимого улучшения финансового результата не обнаружено.

## Итоговая бизнес-рекомендация

По результатам эксперимента переходить на новую схему ценообразования в текущем виде не рекомендуется.

Новая схема:

- увеличивает среднюю цену полиса;
- статистически значимо снижает конверсию;
- показывает более высокую наблюдаемую убыточность;
- не демонстрирует статистически подтверждённого улучшения финансового результата.

### Рекомендация

Сохранить традиционную схему ценообразования как базовую.

Новую модель необходимо доработать и провести повторный A/B-тест после уточнения риск-модели и критериев успеха.

## Следующие шаги

Перед повторным экспериментом рекомендуется:

- определить primary metric;
- зафиксировать guardrail-метрики;
- определить MDE;
- рассчитать необходимый размер выборки;
- заранее определить критерии остановки теста;
- отдельно исследовать убыточность по клиентским сегментам;
- проверить статистическую устойчивость различий по страховым выплатам.

## Ограничения анализа

- `k = 3` выбран как компромисс между математическим качеством кластеризации и бизнес-интерпретируемостью;
- различие в loss ratio рассматривается как наблюдаемое бизнес-различие — отдельная статистическая проверка этого показателя не проводилась;
- страховые выплаты имеют высокую вариативность;
- результаты A/B-теста относятся к конкретной экспериментальной выборке и условиям текущего теста.
